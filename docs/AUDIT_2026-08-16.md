## 1. Audit repo, branch, dan deployment

### 1.1 Posisi branch — **sudah benar**
```
HEAD  = feature/mainlagitv-motion-engine-v3
       63 commit di depan origin/main
       origin/main 0 commit di depan HEAD
```
Semua kerja V3 (engine rebuild, guided tracing, relative mapper, mobile shell) **ada di branch**, bukan di `main`. `main` terakhir bergerak 5 Agustus 2026 (`49b88d2`), branch terakhir 6 Agustus 2026 (`5245ecc`). Jadi kekhawatiran "ini harusnya ada di branch gue" — **posisinya sudah benar**. Yang perlu dipastikan adalah branch mana yang dipakai oleh deployment.

### 1.2 46 file "modified" itu palsu — murni line-ending
```
46 files changed, 14506 insertions(+), 14506 deletions(-)
```
Angka insert dan delete **persis sama**. Ini bukan perubahan kode — ini konversi CRLF↔LF karena bekerja di Windows. Penyebabnya: file `.gitattributes` **hilang dari tree sekarang** (masih ada di snapshot lama).

**Risiko:** commit berikutnya akan menghasilkan diff 14.500 baris yang tidak berarti apa-apa, dan code review jadi mustahil.

**Perbaikan:** kembalikan `.gitattributes` dengan `* text=auto eol=lf`, lalu `git add --renormalize .`.

### 1.3 Tidak ada workflow deploy di repo
`.github/workflows/` hanya berisi `ci.yml`. Tidak ada job deploy. Artinya `mainlagi.inmydraft.com` dideploy dari luar repo (Vercel/Netlify/Cloudflare). **Perlu dikonfirmasi branch mana yang di-hook**, karena kalau yang di-hook `main`, semua kerja V3 belum pernah tayang.

Indikasi dari live site: preflight yang tayang belum menampilkan elemen V3 terbaru (recenter "Tengah", hint trackpad relatif). Tidak konklusif dari HTML saja, tapi patut dicurigai.

### 1.4 Lain-lain
- `preview/` dan `.next/` ikut di folder — pastikan masuk `.gitignore`.
- CI menjalankan `validate:structure`, `audit:source`, `typecheck`, `lint`, `test:engine`, `simulate`, `build` — bagus, gate-nya sudah ketat.

## 2. Skeleton tracking — kenapa "ga ada jarinya"

Kode overlay **sebenarnya sudah menggambar 21 titik + 21 garis jari** (`HAND_CONNECTIONS` di `VisionOverlay.tsx` lengkap). Masalahnya ada di lapisan lain.

### 2.1 🔴 Tangan kedua dibuang diam-diam
`useVisionRuntime.ts`:
```ts
numHands: playerCount === 2 ? 4 : 2   // model mendeteksi 2 tangan
...
if (!player || hands.some((hand) => hand.player === player)) continue;  // ← tangan ke-2 dibuang
```
`assignHandToPlayer` mengembalikan `"A"` untuk **semua** tangan saat `playerCount === 1`. Jadi tangan pertama masuk sebagai A, tangan kedua langsung di-`continue`. **Satu pemain selamanya cuma punya satu tangan di layar.** Di mode 2 pemain pun sama: maksimal 1 tangan per orang, padahal model diminta mendeteksi 4.

Ini penyebab utama kesan "skeleton-nya kurang".

### 2.2 🔴 Pose skeleton cuma 12 garis
`POSE_CONNECTIONS` hanya memuat bahu–siku–pergelangan–pinggul–lutut–pergelangan kaki. MediaPipe Pose memberi **33 landmark**. Yang hilang: seluruh wajah (0–10), telapak tangan (17–22), telapak kaki (29–32), dan garis leher. Jadi tubuh tampil tanpa kepala dan tanpa kaki — persis "ga detail".

### 2.3 🔴 Ukuran gambar tidak skalabel
```ts
context.lineWidth = 3;
context.arc(..., 3, 0, Math.PI * 2);   // radius tetap 3px
```
Radius dan tebal garis konstan berapa pun ukuran kanvas. Di HP, tangan berukuran ~120px lebar → 21 titik radius 3px saling menempel jadi gumpalan. Tidak ada pembedaan ruas jari vs ujung jari, tidak ada warna per-jari, tidak ada skala berdasarkan kedalaman (`z`).

### 2.4 🔴 Overlay meleset dari video di mobile (bug alignment)
```css
.camera-stage > video { width:100%; height:100%; object-fit: cover; }
.vision-overlay      { inset: 0; width:100%; height:100%; }
```
Video 16:9 dirender `object-fit: cover` — di container portrait HP, video **dipotong** kiri-kanan. Tapi `VisionOverlay` memetakan koordinat ternormalisasi (0–1) langsung ke rect kanvas penuh. Hasilnya skeleton bergeser dan meregang dibanding gambar aslinya. Makin jauh dari 16:9, makin meleset.

Ini bukan cuma masalah kosmetik — semua interaksi berbasis posisi (AirCursor, air-target) ikut meleset.

### 2.5 Temuan kecil
- `confidenceOf()` hanya memakai 6 landmark torso.
- `getBoundingClientRect()` dipanggil tiap frame publish.
- Tidak ada penanganan `visibility` untuk landmark tangan (MediaPipe Hand tidak mengisi field itu) — filter `< 0.35` jadi no-op untuk tangan, tapi aktif untuk pose.

Yang dibutuhkan untuk menambahkan:

## 4. Akurasi & presisi tulis — akar masalah "6, 9, 0, 10, 69"

Ini bagian paling dalam masalahnya. Ada **enam** cacat yang saling menumpuk.

### 4.1 🔴 Matcher menerima bentuk cermin DAN terbalik
`src/lib/engine/digit.ts`:
```ts
return Math.min(
  pathDistance(input, target),
  pathDistance(mirrored, target),          // ← menerima tulisan dicermin
  pathDistance(input, [...target].reverse())  // ← menerima tulisan dibalik arah
);
```
**6 dan 9 adalah rotasi 180° satu sama lain.** Dengan menormalisasi posisi (centroid-center) lalu menerima cermin dan pembalikan urutan, ruang perbedaan antara 6 dan 9 nyaris hilang. Ini **secara matematis** menjelaskan kenapa 6 dan 9 tertukar.

Hal yang sama membunuh: 2 vs 5, 0 vs 8 (sebagian).

Untuk huruf Arab lebih parah lagi — `scorePath()` di `geometry.ts` juga melakukan mirror-match. Tulisan Arab itu RTL dan **arah adalah bagian dari identitas huruf** (د vs ر, ذ vs ز). Mencerminkan input membuat huruf-huruf ini tumpang tindih.

### 4.2 🔴 Pen-up diabaikan — stroke digabung jadi satu garis
```ts
function merged(strokes) { return significant.flatMap((stroke) => stroke.points); }
```
Semua stroke disambung ujung-ke-ujung, jadi angkat-jari membuat **garis hantu** yang menghubungkan akhir stroke 1 ke awal stroke 2. Untuk angka 4 dan 5 (dua stroke) ini merusak bentuk total.

Ironisnya `geometry.ts` sudah punya `flattenStrokes()` dengan pemisah NaN — tapi **tidak pernah dipakai** oleh `digit.ts`.

### 4.3 🔴 Satu template per angka
`DIGIT_TEMPLATES[6]` cuma punya **satu** varian polyline. Tulisan tangan manusia bervariasi: 4 tertutup vs terbuka, 7 dengan/tanpa palang, 9 ekor lurus vs melengkung, 1 dengan/tanpa serif. Satu template tidak akan pernah cukup, apalagi untuk tangan anak 5 tahun.

### 4.4 🔴 Matcher-nya paling primitif
`pathDistance` = rata-rata jarak Euclidean titik-ke-titik **berdasarkan indeks** setelah resample ke 64 titik. Tidak ada:
- pencarian rotasi (Golden Section seperti $1 recognizer)
- pencocokan tak-berurutan (seperti $P point-cloud)
- fitur turunan (jumlah belokan, arah awal, rasio aspek, jumlah persilangan)
- toleransi kecepatan (DTW)

Threshold-nya angka ajaib tanpa kalibrasi: `0.43`, `0.16`, `0.48`, `0.5`.

### 4.5 🔴 Angka lebih dari 1 digit tidak benar-benar didukung
Untuk menulis **10** atau **69**, anak harus:
1. cubit → tulis "1" → buka telapak, **tahan 700 ms** → submit
2. cubit → tulis "0" → buka telapak, tahan 700 ms → submit

Tidak ada segmentasi glyph multi-digit. Untuk anak 5 tahun ini praktis tidak bisa. Ditambah: `verifyExpectedDigit` hanya membandingkan dengan digit **yang diharapkan** — jadi sistem bilang "benar" untuk bentuk yang cuma mirip-mirip, sementara `classifyDigit` (untuk penalti) pakai ambang berbeda. Dua jalur penilaian yang tidak konsisten.

### 4.6 🔴 Pena udara relatif = akumulasi noise (ini yang bikin "ga presisi")
`RelativeHandMapper` bekerja seperti trackpad: `cursor += (Δtangan) × gain`.

Masalahnya, ini **mengintegrasikan** posisi. Setiap sisa jitter yang melewati `deadZone` (0,0015) ikut tertambah dan **tidak pernah dikoreksi** — random walk klasik. Efek nyatanya: garis lurus perlahan melengkung, lingkaran tidak menutup, dan pena "melayang" menjauh sampai user menekan tombol "Tengah".

Mapping relatif itu tepat untuk memilih menu, **salah** untuk menulis, karena menulis butuh kesetiaan bentuk absolut.

### 4.7 🔴 Awal setiap stroke terpotong
- `GestureLatch(enterFrames = 3)` → pinch baru diakui setelah 3 frame ≈ **100–150 ms**
- `CAMERA_RELEASE_GRACE_MS = 170` di pen-up
- `appendPoint(..., 0.0025)` membuang gerakan halus
- `points.slice(-319)` **membuang awal stroke** setelah 320 titik — stroke Arab yang panjang kehilangan pangkalnya

Jadi setiap huruf kehilangan ~150 ms pertama. Untuk angka 6 yang dimulai dari lengkungan atas, bagian pembeda utamanya justru yang hilang.

### 4.8 🔴 `hand.confidence` bukan confidence gesture
```ts
const confidence = handResult?.handedness[index]?.[0]?.score ?? analyzed.confidence;
```
Ini skor **handedness** (kiri/kanan), yang hampir selalu >0,95. Nilai `analyzed.confidence` dari `analyzeGesture()` — satu-satunya angka yang benar-benar mengukur keyakinan gesture — **dibuang**.

Akibatnya `MIN_HAND_CONFIDENCE = 0.38` di `MotionPad` dan semua cek serupa **tidak berfungsi sama sekali**.

### 4.9 Huruf Hijaiyah — masalah tersendiri
`hijaiyah.ts`:
- **Stroke terpanjang dianggap badan huruf.** Kalau anak menulis titik pelan-pelan (banyak titik data), titik itu jadi "badan" dan huruf jadi salah total.
- **ب / ت / ث / ن memakai `BOWL` yang identik**; pembedanya cuma jumlah titik dan posisi atas/bawah. Nun (ن) sebenarnya mangkuknya jauh lebih dalam dari Ba (ب).
- Ambang zona titik `bodyBox.minY + height*0.4` salah untuk badan berbentuk mangkuk.
- Baru **14 dari 28 huruf**.
- Tidak ada pengecekan arah tulis (RTL) padahal itu inti pembelajaran Iqro.
- `evaluateHijaiyah` ditulis dalam satu baris raksasa — praktis tidak bisa dirawat atau diuji.

## 5. Playability — anak 5 tahun & main berdua

### 5.1 🔴 Preflight punya 7 gerbang
Untuk sampai ke game, harus lolos: kamera → model → tangan terdeteksi → tubuh terdeteksi → cubit dikonfirmasi → telapak terbuka dikonfirmasi → jempol ke atas ditahan 900 ms.

Anak 5 tahun tidak akan lolos ini sendirian. Dan di mode 2 pemain untuk game tangan, `needsBodies` jadi `true` — butuh **2 tubuh utuh + 4 tangan** terdeteksi di 960×540. Di ruang keluarga biasa, ini sering gagal.

### 5.2 🔴 Level dipakai bersama antara anak 5 th dan ayah 36 th
`DigitRace` punya **satu** state `level` dan **satu** `question` untuk kedua pemain. Anak dan ayah mengerjakan soal yang sama, tanpa handicap. Ayah menang telak setiap kali. Ini masalah desain paling besar untuk mode berdua.

### 5.3 🔴 Jawaban benar pemain A menghapus input pemain B
```ts
lockedRef.current = true;
setTimeout(() => { setDigits({ A: "", B: "" }); ... }, 850);
```
Ketika A benar, seluruh papan terkunci dan buffer **kedua** pemain dikosongkan. Kerja B yang sedang setengah jalan hilang.

### 5.4 🔴 Penalti dan tekanan waktu
- Salah digit: **−5 poin**
- Timer 60 detik di semua game
- Gagal: cuma dapat teks bahasa Indonesia yang anak 5 tahun belum bisa baca

Tidak ada mode latihan tanpa timer, tidak ada suara, tidak ada perayaan visual.

### 5.5 🔴 Soal selalu sama persis
```ts
const [random] = useState(() => createRandom(seedFor(kind)));  // seed tetap 0x51aa
```
Seed di-hardcode. **Urutan soal identik setiap sesi.** Tidak ada nilai main ulang.

### 5.6 🔴 Tombol tidak bisa dijangkau tanpa mouse
Tombol level (TK/SD1/SD2), pemilih angka, pemilih bentuk, dan tombol di layar akhir ronde **tidak punya `data-air-target`**. `AirCursor` hanya dipakai di AirBoard. Jadi di mode kamera, anak tidak bisa mengganti apa pun tanpa mouse — padahal premisnya "touchless".

### 5.7 Lain-lain
- Timer terus jalan meski anak keluar dari frame kamera.
- Tidak ada auto-pause saat tangan hilang.
- `RoundEndOverlay` tidak bisa dioperasikan lewat gesture.

## 6. Frontend — desktop & mobile

### 6.1 🔴 `100vh` + `min-height: 680px`
```css
.camera-stage { height: calc(100vh - 68px); min-height: 680px; }
```
Di HP, `100vh` tidak memperhitungkan address bar yang muncul/hilang → konten melompat. Dan `min-height: 680px` **memaksa scroll vertikal** di HP kecil pada layar yang seharusnya fullscreen. Harus `100dvh` dan `min-height` dilepas di mobile.

### 6.2 🔴 CSS terpecah dan bertabrakan
- `globals.css` — 537 baris, satu baris = satu selector panjang
- `mobile.css` — 693 baris, menimpa globals lewat `@media (max-width: 760px)`
- 3 CSS module terpisah
- Breakpoint tidak konsisten: 1050 / 760 di globals, 761 / 760 / 960-landscape di mobile

Total 1.230 baris CSS untuk 9 game, dengan aturan mobile yang menimpa desktop alih-alih mobile-first. Sulit dirawat, dan itu terlihat di hasilnya.

### 6.3 🔴 Skeleton meleset dari video (lihat §2.4)
Ini bug frontend sekaligus bug presisi.

### 6.4 HUD terlalu padat untuk anak
`.game-hud` grid `180px 1fr 180px`, di mobile jadi `100px 1fr 100px` dengan `font-size: 7px` untuk label skor. Tujuh piksel. Tidak terbaca.

`.hud-center span { display: none }` di mobile — judul game hilang.

### 6.5 Target sentuh di bawah standar
Tombol `.number-strip`, `.level-switch`, `.shape-picker` tidak dijamin 44×44 px. Untuk jari anak, minimal harus 56 px.

### 6.6 Tidak ada mode landscape yang layak
Hanya ada satu query `(orientation: landscape) and (max-height: 560px)`. Padahal game kamera **paling nyaman dimainkan landscape** — ini seharusnya orientasi utama di HP, bukan kasus tepi.

## 7. Rekomendasi perbaikan (urutan prioritas)

### Prioritas 1 — memperbaiki yang rusak
1. **Kembalikan `.gitattributes`**, `git add --renormalize .`, bersihkan 46 file palsu
2. **Tangan kedua**: hapus dedup per-pemain, dukung 2 tangan/pemain dengan slot kiri-kanan
3. **Alignment overlay**: hitung transform `object-fit: cover` (skala + offset) sebelum menggambar; pakai satu fungsi proyeksi bersama untuk overlay, AirCursor, dan air-target
4. **Buang mirror-match** dari `digit.ts` dan `geometry.ts` sepenuhnya
5. **Hormati pen-up**: pakai `flattenStrokes` / matcher per-stroke, bukan `flatMap`
6. **Perbaiki `hand.confidence`**: simpan skor gesture asli di field terpisah (`gestureConfidence`)

### Prioritas 2 — akurasi tulis
7. **Ganti recognizer** ke $P point-cloud + fitur turunan (arah awal, jumlah belokan, rasio aspek, persilangan). Khusus 6/9/2/5 tambahkan diskriminan eksplisit berbasis posisi loop (loop di bawah = 6, loop di atas = 9)
8. **Multi-template per angka** — minimal 3 varian tiap digit, termasuk varian tulisan anak
9. **Ganti pena relatif → absolut terkalibrasi**: saat preflight, rekam kotak jangkauan tangan user, lalu petakan absolut ke kanvas. Hilangkan drift sepenuhnya
10. **Turunkan latch pinch** ke 2 frame + buffer pra-pinch 150 ms (rekam titik sebelum pinch diakui, sambung retroaktif) supaya awal stroke tidak hilang
11. **Multi-digit dalam satu tulisan**: segmentasi berdasarkan celah spasial + waktu, jadi "69" bisa ditulis sekali jalan
12. **Rombak `hijaiyah.ts`**: pemisahan badan/titik berbasis bounding-box bukan panjang stroke, template per-huruf yang benar, cek arah RTL, lengkapi 28 huruf

### Prioritas 3 — face mesh
13. Tambah `FaceLandmarker` + aset model + overlay tessellation
14. Gunakan untuk hal yang berguna, bukan hiasan:
    - **Preflight**: cek anak menghadap kamera & jarak pas
    - **Player assignment**: identitas pemain lewat posisi wajah (jauh lebih stabil daripada slot tubuh)
    - **Input alternatif**: buka mulut / kedip sebagai "kirim" — jauh lebih mudah bagi anak 5 tahun daripada menahan telapak 700 ms
    - **Auto-pause** saat wajah keluar frame

### Prioritas 4 — playability
15. **Preflight ringan**: satu langkah "lambaikan tangan" untuk anak; checklist lengkap disembunyikan di balik "Mode orang tua"
16. **Level & soal terpisah per pemain**, dengan auto-handicap (anak dapat waktu lebih & soal TK, ayah SD2)
17. **Hapus penalti −5**; ganti dengan bintang/progres
18. **Mode latihan tanpa timer** sebagai default untuk usia 4–6
19. **Seed acak per sesi**
20. **Suara & animasi**: TTS Indonesia untuk soal, bunyi benar/salah, konfeti — anak 5 tahun belum bisa baca
21. **`data-air-target` di semua tombol** + AirCursor aktif di semua game
22. **Auto-pause** saat pemain hilang dari frame

### Prioritas 5 — frontend
23. **Tulis ulang CSS jadi mobile-first**, satu file token + satu file layout, breakpoint tunggal 768/1024
24. `100dvh`, buang `min-height: 680px` di mobile, `env(safe-area-inset-*)`
25. **Landscape sebagai orientasi utama** di HP untuk game kamera, dengan petunjuk putar layar
26. **Target sentuh ≥ 56 px**, ukuran font minimum 12 px, HUD disederhanakan jadi 3 elemen (skor, waktu, jeda)
27. **Bahasa visual untuk anak**: ikon besar, warna tinggi kontras, teks minimal
