# Mainlagi Learning Platform — Mobile-First Amendment

Status: **normative amendment to the canonical UX specification**.

This amendment exists so agents do not misread the instruction to preserve the motion engine as an instruction to force camera motion into the whole product.

The broader Mainlagi child learning experience is **mobile-first and touch-first**.

Preserve:

- the existing MediaPipe motion engine;
- all existing motion games;
- direct access to `Main Gerak` / motion experiences.

But do **not** require motion capture for core curriculum learning when a simpler phone/tablet interaction is more appropriate.

For implementation details and input-mode rules, `docs/MOBILE_FIRST_INTERACTION_STRATEGY.md` is canonical.

Where this amendment conflicts with older wording that implies motion should be a default product identity or default activity path, this mobile-first policy takes precedence. Motion remains a first-class optional capability and differentiator.
